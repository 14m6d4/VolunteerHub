# Architecture

VolunteerHub is two packages in one repository, each with its own `package.json`: `backend/`, a REST API in Express 5 and TypeScript, and `frontend/`, a React 19 single-page app built with Vite. Both talk JSON over `/api`. In production they sit behind the same Traefik router, so the browser sees one origin. The [README](../README.md#architecture) has the infrastructure diagram.

## Backend

### Layers

A request goes through the same layers in every domain, with one file per domain at each layer:

```
routes/*.routes.ts → middlewares/ → controllers/*.controller.ts → services/*.service.ts → db/schema.ts
```

- Routes pick the middleware chain and the controller method.
- Controllers parse the request, call one service and answer `{ success: true, data }`. Errors go to `next(err)`.
- Services hold the business logic and every Drizzle query. A service throws `AppError(message, status)` or an `http-errors` error to choose the response.
- `db/schema.ts` defines the PostgreSQL tables and enums. Migrations are plain SQL in `backend/drizzle/`, generated by drizzle-kit.

`error.middleware.ts` is registered last and turns every error into `{ status, message }`, adding the stack trace outside production.

In development `tsx` runs the TypeScript sources directly. Production runs the `tsc` output from `dist/`. Imports between project files keep their `.ts` extension, which `tsc` rewrites to `.js`.

### API domains

| Domain | Prefix | Covers |
| --- | --- | --- |
| Auth | `/api/auth` | sign-up, email verification codes, login, password reset, current user |
| Events | `/api/events` | listing, create, edit, delete, admin approval, completion |
| Registrations | `/api/register` | sign up for or leave an event; approve, reject or remove a volunteer |
| Discussions | `/api/groups` | the posts in an event's discussion |
| Posts | `/api/posts` | create with an image, like, delete, read one |
| Comments | `/api/comments` | comment on a post, delete |
| Feed | `/api/feed` | the personal feed |
| Users | `/api/users` | profiles, search, settings, admin user management |
| Friends | `/api/users/friends` | friends, friend requests, friend suggestions |
| Notifications | `/api/notifications` | inbox, unread count, mark read, delete |
| Reports | `/api/report` | file a report, list, resolve or reject |
| Admin | `/api/admin` | analytics |

`/api/health` checks the database and answers 503 when it is unreachable. `/uploads` serves the stored images, and `/metrics` serves Prometheus metrics to the monitoring agent only.

### Middleware

- `authMiddleware` requires a `Bearer` JWT and loads the user onto `req.user`; it rejects banned users. `optionalAuthMiddleware` attaches the user when a token is present and never rejects, for public pages that still show personal state, such as the event list.
- `roleMiddleware([...])` checks `req.user.role` (`volunteer`, `manager` or `admin`).
- `validateBody`, `validateQuery` and `validateParams` parse the input with Zod schemas from `utils/validators.ts` and replace it with the parsed value.
- `uploadImage(field)` accepts one image of up to 2 MB, held in memory.
- `rateLimit.middleware.ts` limits login and sign-up to 20 requests per 15 minutes per client, and verification codes and password resets to 8. The client is identified by Cloudflare's `CF-Connecting-IP`.
- `observability.middleware.ts` gives every request an ID (it echoes `X-Request-Id` or makes one), logs one JSON line per request with pino, and records request rate, errors and latency per route with prom-client.

`app.ts` also sets security headers with Helmet, allows CORS only from `FRONTEND_URL` and the Vite dev server, and caps JSON bodies at 1 MB.

### Authentication

Sessions are stateless: the API signs a JWT at login and the frontend sends it as a `Bearer` token. A new account has to confirm its email with a one-time code sent through Nodemailer before it can log in, and password reset uses the same kind of code. Passwords are hashed with bcrypt.

When the database connects and no admin exists yet, `config/db.ts` creates one from `SEED_ADMIN_EMAIL` and `SEED_ADMIN_PASSWORD`. Both are unset by default, which skips this step.

### Images

`services/image.service.ts` re-encodes every upload to WebP with sharp. It applies the EXIF orientation, strips the metadata (phone photos carry GPS coordinates), caps the long edge at 1600 px and saves the file under a random name in `UPLOADS_DIR`, a Docker volume in production. The database stores the `/uploads/<name>.webp` path. Uploads are refused once the folder holds 5 GB, and replacing or deleting an image's owner (profile picture, cover image, post, event, user) deletes the old file. [ADR 0002](adr/0002-store-uploads-on-the-vm.md) explains why images live on the VM.

## Frontend

- `src/App.tsx` declares every route with React Router 7, grouped by layout: pages with the navbar and footer, the admin pages with a sidebar, and bare auth pages. `ProtectedRoute` wraps the routes that need a role.
- The provider stack, outermost first, is `QueryProvider` (TanStack Query), `AuthProvider`, `ThemeProvider` and `BrowserRouter`.
- `src/context/AuthContext.tsx` owns the logged-in user. The JWT is kept in `localStorage` under `accessToken`. Setting or clearing it fires an `authTokenChanged` event that reloads the context, and a banned user is sent to `/banned`.
- Every request goes through `apiFetch` in `src/services/api.ts`, which adds the base URL and the auth header and turns error bodies into thrown `Error`s. Each domain has a `src/services/*.service.ts` file of plain async functions, and components reach them through hooks in `src/hooks/`. Notifications are fetched again every 30 seconds.
- UI primitives in `src/components/ui/` are generated by shadcn/ui on top of Radix. Feature components live in `src/components/<feature>/` and pages in `src/pages/`. The `@` import alias points at `src/`.
- `ThemeProvider` handles light, dark and system mode and the 9 color themes. Each theme is a CSS file in `src/styles/themes/` that is loaded when picked, together with its Google Fonts. Both choices are stored in `localStorage`.

`src/pages/test/` and `src/data/*-mock.ts` are scratch code and are not part of the app.

## Data

PostgreSQL holds every domain; the move from MongoDB is recorded in [ADR 0001](adr/0001-move-from-mongodb-to-postgresql.md). Each event has one discussion, which is deleted with it. A post belongs to an event, to a discussion, or to neither, and goes away with its parent. The words used for these concepts are defined in the [glossary](../GLOSSARY.md).
